# Fork releases

Run the registered **Build** workflow manually on **develop**, or ask an agent to use `$buddy-release` (`/buddy-release` in Claude Code). Pushes and merges to develop do not release. Its optional `version` input accepts `vX.Y.Z`, `X.Y.Z`, or either with `-zees.N`; leave it empty for the next fork version.

The empty-input rule chooses the highest supported version base among source and fetched tags, then increments that base’s largest `zees.N` suffix (including the source version). Initially, `2.2.26-zees.1` becomes `v2.2.26-zees.2`. An explicit version must advance the base or fork sequence and cannot reuse a tag. A bare X.Y.Z must advance the base because Buddy’s updater ranks it below that base’s fork suffixes. Android’s version code exceeds the source and all fetched tag codes. The workflow commits only BuildInfo’s version change; builds and validates it; then atomically advances develop and creates its tag. If develop moved during the build, it stops without pushing. Dispatch again from current develop after inspecting the failure.

The workflow serializes builds, runs helper fixtures and both release variants, and checks F-Droid reproducibility before publication. It verifies the GitHub APK’s package, version, non-debuggable flag, single signer pinned in source and 16 KB ZIP/native alignment. It publishes `buddy.apk`, a versioned copy, `SHA256SUMS` and `release.json` through a draft release, marking it latest only after uploads succeed. Failed publication may leave a tag or draft; inspect and recover explicitly without overwriting existing releases.

GitHub Actions secrets: `BUDDY_KEYSTORE_BASE64`, `BUDDY_KEYSTORE_PASSWORD`, `BUDDY_KEY_ALIAS`, `BUDDY_KEY_PASSWORD` and `BUDDY_SIGNER_SHA256`. Missing signing configuration blocks release. The user approved storing the existing compatible signing identity in encrypted secrets for this fork. The expected certificate SHA-256 is `1bb834b7164eb3f1f54d02e26171363979e1ee93ed8420487d80cc3e5572111c`. This remains a compatibility/test signer; a production identity migration is separate. Keys/passwords never enter source, assets or logs. Repository writers who can modify the dispatched workflow can access signing secrets: protect that access accordingly.

The workflow is kept in `build.yml` because that workflow is already registered on the default branch, main. Dispatch with `--ref develop`; no default-branch change is needed. Its Actions web form on main may not show develop’s optional input, so use the skill/CLI for explicit versions. Never dispatch a release from main.

Latest release: <https://github.com/zees-dev/buddy-android/releases/latest>. Direct APK: <https://github.com/zees-dev/buddy-android/releases/latest/download/buddy.apk>. The release is stable on GitHub even though the fork uses a semver suffix, so Buddy’s updater can find it. Android’s installer stays human-controlled. Updating may stop Buddy’s SSH terminal; reopen it and run `sh /root/bin/phone-link`.
